**Date:** 2026-09-29  
**Status:** Frozen

## Visual Style

Warm and personal. Soft off-white background, muted warm accent colour. No corporate feel. Simple, uncluttered. Family app — should feel approachable to a non-technical user.

Colour palette (to be refined in implementation):
- Background: `#FDF8F4` (warm off-white)
- Accent / primary button: `#C17A3A` (warm amber)
- Text: `#2D2016` (warm near-black)
- Input border: `#E0D0C0`

---

## Screen Flow

```
App launch
  │
  ├─ Prior GKS URL stored?
  │    ├─ YES → Login screen
  │    └─ NO  → Server discovery screen → Login screen
  │
  └─ Login screen
       ├─ Online + valid credentials → Home (no storage gate — local storage, ADR-0009)
       ├─ Online + wrong credentials → Inline error, retry
       ├─ Offline + prior login exists → Offline login → Home (OFFLINE mode)
       └─ Offline + 3 failed attempts → Lockout screen
```

## Server Discovery Screen

Shown only on first launch or when stored URL becomes unreachable and user initiates re-discovery.

### Auto-discovery (primary)
1. App scans Tailscale network: probes each peer with `GET <peer>/api/v1/health`
2. Collects all peers that respond with HTTP 200
3. **If exactly one found:** auto-selects it, shows "Found your GKS server at `<hostname>`" with a Confirm button
4. **If multiple found:** shows a list — each item displays hostname + Tailscale IP; user taps to select
5. **If none found:** shows "No GKS server found" with a "Scan again" button and a "Scan QR code instead" option

### QR fallback
- Shown when auto-discovery finds nothing, or user taps "Use QR code"
- Opens device camera in QR scan mode
- QR encodes the GKS base URL (generated by GKS admin panel — GKS-side feature, see GKS-API-extensions.md)
- On successful scan: URL extracted, health-probed, then stored

### Stored URL
- Saved to `expo-secure-store` under key `gks_server_url`
- Reused on all subsequent launches — discovery never runs again unless user resets it from Settings

## Offline Login UX

1. User taps "Continue offline"
2. Same login screen — username and password fields remain
3. App verifies password against device-local Argon2id verifier (ADR-0003)
4. On match: enter home screen; persistent offline status dot shown in app header
5. On mismatch: show "Incorrect password" inline error; increment offline attempt counter
6. After 3 failures: transition to lockout screen

## App-wide Offline Status Dot

A small status dot lives in the app header (top-right, next to user name) on **every screen** — not just the home screen.

| State | Dot | Label |
|---|---|---|
| GKS online, synced | 🟢 | `GKS · <time ago>` |
| GKS online, syncing | 🟡 | `Syncing…` |
| GKS offline / unreachable | 🔴 | `Offline` |
| Cloud storage unavailable | 🟠 | `Storage unavailable` |

Tapping the dot opens a sync/status detail screen (designed separately).
Dot is small and unobtrusive — single emoji + short label. Not a banner.

## Credential Storage (Secure Enclave)

All stored in `expo-secure-store` (backed by iOS Keychain / Android Keystore):

| Key | Value | Purpose |
|---|---|---|
| `gks_server_url` | GKS base URL string | Server discovery persistence |
| `gks_username` | Username string | Silent re-auth |
| `gks_password_enc` | Encrypted password | Silent re-auth (AES-GCM, key in enclave) |
| `offline_verifier` | Argon2id hash | Offline login |
| `offline_verifier_salt` | Salt bytes | Offline login |
| `offline_attempt_count` | Integer string | Lockout tracking |

---

## Silent Session Re-authentication

When the GKS session cookie expires (8h absolute, 30min idle) while the app is online:
1. Any API call returns 401
2. App intercepts 401, silently calls `POST <gks>/api/v1/auth/login` using stored credentials
3. On success: new session cookie stored, original API call retried — user sees nothing
4. On failure (credentials rejected — e.g. password changed in GKS): show login screen with message "Your session has expired — please log in again"

---

## Storage

Local device only (ADR-0009). No cloud storage setup screen. No OAuth gate. Records go to `expo-sqlite` + `expo-file-system` app sandbox immediately after login. Always available, no external dependency.

---

## What This Design Does NOT Include

- Biometric login — post-V1 (REQ-0004 out of scope)
- Multi-account / multiple GKS instances — not planned
- "Remember me" checkbox — always remembers (offline verifier is always set on login)
